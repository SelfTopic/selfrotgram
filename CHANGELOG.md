# История изменений

Формат: [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии: [SemVer](https://semver.org/lang/ru/).
Пока версия `0.x`, минорная версия играет роль мажорной: **ломающие изменения увеличивают
минор** (`0.1` → `0.2`), исправления и совместимые добавления увеличивают патч (`0.1.0` →
`0.1.1`). Поэтому `poetry add` записывает `^0.1.0`, то есть `>=0.1.0,<0.2.0`.

## [0.1.12] — 2026-10-15

### Добавлено
- `mention_html(user)` / `mention_html(telegram_id, name)`: кликабельное упоминание без
  username (`<a href="tg://user?id=...">`) — для сообщения из апдейта (имя из `User`) или
  когда под рукой только `telegram_id` и имя строкой (тикер, сервис, запись из базы). Имя
  экранируется само — не нужно оборачивать каждый вызов в `html.escape()` руками
- пример в `examples/reply_bot.py`: `/warn` отвечает кликабельным упоминанием нарушителя

## [0.1.11] — 2026-10-15

### Добавлено
- `Dispatcher.tasks`: фоновые периодические задачи (`Every(interval, ВашКласс)`,
  `BaseTask`) — задача получает `ctx` того же типа, что и хендлер, прошедший те же
  мидлвари диспетчера (сессия БД, сервисы работают так же, как в хендлере); апдейта за
  вызовом нет — `ctx.is_background` говорит об этом явно, не угадывание по пустым полям.
  Старт и остановка — вместе с `polling()`/`webhook()`, не нужно вручную заводить в
  `__main__.py`; остановка не обрывает уже начавшуюся задачу, только то, что ещё спит.
  Ошибка — `on_error` у самой задачи (как у хендлера), не обработали сами — в `on_error`
  диспетчера
- пример `examples/tasks_bot.py`

## [0.1.10] — 2026-10-15

### Добавлено
- deep link (`t.me/<bot>?start=...`): `StartPayload` — типизированные данные ссылки, свой
  алфавит `[A-Za-z0-9_-]` и лимит 64 символа (Telegram молча портит ссылку вне них — проверка
  при упаковке, а не после отправки пользователю); `.url(bot)` собирает ссылку сам;
  `Command("start", СвояМодель, deep_link=True)` разбирает её тем же `.parse(ctx)`, что и
  обычные аргументы команды. Голый `Command("start", deep_link=True)` не забирает чужой
  deep-link токен (похожий на `[A-Za-z0-9_-]+` без пробелов) — больше не нужно следить за
  порядком хендлеров, чтобы специфичный разбор ссылки стоял раньше общего `/start`
- пример `examples/deep_link_bot.py`

## [0.1.9] — 2026-10-15

### Добавлено
- `Dispatcher.on_unhandled_callback(ctx, callback_query)`: нажатие кнопки, которое не
  досталось ни одному хендлеру ни в одном роутере, иначе оставляет на кнопке бесконечно
  крутящиеся «часики» (Telegram ждёт `answerCallbackQuery`). По умолчанию — предупреждение
  в лог и пустой `answer_callback_query()`; переопределяется, как `on_error`: свой алерт
  или полностью отключить (пустое тело). Для остальных видов апдейта тишина остаётся нормой

## [0.1.8] — 2026-10-15

### Добавлено
- заголовок хендлера ищется по всей цепочке наследования (MRO), а не только среди
  собственных оснований класса: миксин теперь может сам писать `MessageHandler[TContext]`
  (обычным generic-классом, дженериком и по контексту, и по своим аргументам), финальному
  классу не нужно повторять его как отдельное основание
- `MessageNotModified`, `MessageToEditNotFound` — подклассы `TelegramBadRequest` для двух
  частых игнорируемых ошибок Telegram (правка без изменений; сообщение уже недоступно),
  распознаются по тексту `description` при разборе ответа

## [0.1.7] — 2026-10-14

### Исправлено
- `selfrot check`/`tree` считали хендлер с ветками-декораторами «без фильтра, ловит всё
  этого вида» (у такого хендлера `query` всегда `None` — проверка недостижимости смотрела
  именно на `query`, не зная о ветках в `_entries`): все хендлеры того же вида апдейта ниже
  по дереву ложно считались недостижимыми, `--strict` падал. Анализ теперь считает хендлер
  с ветками ловящим апдейт, если его забирает хотя бы одна ветка (их фильтры через `|`)
- `selfrot tree` печатает ветки такого хендлера по одной строке (имя метода и фильтр), а не
  общей надписью «без фильтра»

## [0.1.6] — 2026-10-14

### Исправлено
- `DefinitionError` «хендлер пуст» ложно срабатывал, если `handle()` даёт не сам класс, а
  миксин выше по цепочке наследования (частый приём: миксин держит `handle()` и зовёт
  переопределяемый `perform()`, финальный класс только добавляет `query`) — проверка смотрела
  только на сам класс (`vars(cls)`), не на всю цепочку наследования. То же самое ломало и
  проверку «нельзя писать handle() вместе с декораторами»: handle() от миксина проходил
  незамеченным

## [0.1.5] — 2026-10-14

### Добавлено
- упоминания без username (кликабельное имя, Telegram подставляет его из списка участников,
  сущность `text_mention`): `entity_text(text, entity)` — текст сущности по offset/length в
  UTF-16 code units (как считает Telegram, а не по кодовым точкам Python — иначе съезжает
  после эмодзи и подобных символов); `mentions(message)` — все такие упоминания сообщения
  (text или caption — сама разбирается, какое) с пользователями внутри; `ctx.mentions()` —
  ярлык для `mentions(ctx.message)` на текущем апдейте; фильтр `HasMention()`
- несколько веток одной команды в одном хендлере: фильтр применяется к методу как обычный
  декоратор (`@cmd.where(command=X) & HasReplyUser()`), первая подошедшая ветка вызывается —
  вместо того, чтобы заводить отдельный класс на каждую ветку. `query` класса при этом
  остаётся `None`, а `handle()` не переопределяется; смешивать стили — `DefinitionError` при
  импорте. Работает для любого вида хендлера (`MessageHandler`, `CallbackQueryHandler`, ...)
- `Command.where(поле=значение)`: та же команда, но подходит только если указанные поля уже
  разобранных аргументов равны значениям (нужна модель аргументов)
- пример `examples/fun_bot.py`
- `View`: самообновляющееся сообщение — хендлер не видит ни `edit_message_text`, ни
  `callback_query.answer()`, ни разбора данных кнопки. `render(ctx, data)` — текущее
  содержимое (`ViewContent`: текст или `InputRichMessage` плюс свои ряды кнопок), `data`
  — то, что только что нажали (`None` при первом показе); `apply(ctx, data)` — что сделать
  с состоянием (обычно в БД) до повторного `render`, по умолчанию ничего не делает;
  `show(ctx)`/`press(ctx)`/`filter()` — вся механика отправки, правки и ответа на callback
- `Pagination(View)`: частный случай с номером страницы — навигационный ряд («« N/M »»),
  проверка границ, опциональная кнопка закрытия (`closable=True`, по умолчанию удаляет
  сообщение, `closed()` переопределяем) берёт на себя сама; вместо `render`/`payload`
  реализуются `total(ctx)` и `page_content(ctx, page)`
- пример `examples/pagination_bot.py`: каталог на страницах с кликабельными товарами
  (`Pagination`) и счётчик (`View` напрямую)

## [0.1.4] — 2026-09-22

### Добавлено
- скачивание файлов: `ctx.download(destination)` находит файл текущего апдейта сам (у фото —
  самый большой размер, иначе animation/audio/document/sticker/video/video_note/voice — что
  заполнено; ничего нет у самого сообщения — смотрит ещё в `reply_to_message`), пишет на диск
  и отдаёт `Path`; нет расширения у `destination` — дописывается из оригинального имени файла
  (`file_name` есть у `animation`/`audio`/`document`/`video`), а если его нет — из настоящего
  `file_path` (`.jpg`, `.oga`, ...); заданное расширение не трогается;
  `Bot.download(file_id)` — байты по id без апдейта (`get_file` + `download_file`);
  `Bot.download_file(file_path)` — сырые байты по известному пути, отдельный URL,
  не через `call()`
- `ctx.download(destination, overwrite=False)`: не заменяет существующий файл, а подбирает
  первое свободное имя (`" (1)"`, `" (2)"`, ...); по умолчанию `overwrite=True` — как раньше,
  молча заменяет
- `FileNotAvailableError`: `getFile` не вернул `file_path`
- пример `examples/download_bot.py`

## [0.1.3] — 2026-09-22

### Добавлено
- условия над ответом на сообщение: `Reply[T]` и 13 готовых пар (`user`, `text`, `entities`,
  `caption`, `caption_entities`, `photo`, `animation`, `audio`, `document`, `sticker`, `video`,
  `video_note`, `voice`): типы `ReplyUserMessage`, `ReplyPhotoMessage`, ... и фильтры
  `HasReplyUser`, `HasReplyPhoto`, ... (генерируются; список в `REPLY_ATTRS` в
  `scripts/generate_types.py`). Несколько условий: `Reply[PhotoCaption]`, где
  `PhotoCaption` собран наследованием, и фильтр `HasReplyPhoto() & HasReplyCaption()`
- пример `examples/reply_bot.py`: бот на 9 команд, которые работают в ответ на сообщения (готовые
  условия, несколько условий сразу, «любое из», `if`, подсказка после всех команд)

### Изменено
- проверка заголовка хендлера сверяет и вложенные поля: гарантия фильтра теперь может содержать
  пути вроде `reply_to_message.user`. Раньше заголовок с вложенным суженным типом проходил проверку,
  даже если фильтр проверял только внешнее поле; теперь это `DefinitionError` при импорте

## [0.1.2] — 2026-09-22

### Добавлено
- `AnyCommand`: несколько триггеров у одной команды (`/transfer`, «перевести», «кинуть») с
  разными именами, префиксами и регистром. `parse(ctx)` разбирает аргументы сработавшей
  команды и возвращает модель (или `A | B`, если модели разные), `find(ctx)` отдаёт саму
  команду, `CommandArgsError.usage` содержит слово, которым позвали
- `Command.matches(ctx)`: то же, что `check`, но обычным вызовом
- `selfrot tree` печатает `AnyCommand` в несколько строк, как пишется в коде (ветки дерева не
  рвутся, пометка «недостижим» стоит после закрывающей скобки)
- `selfrot tree` печатает длинную цепочку `&`/`|` по одному операнду на строку вместо вложенных
  скобок (`a & b & c`, а не `((a & b) & c)`); причина «недостижим» в `tree` и `check` тоже без
  вложенных скобок

### Изменено
- `TParsed` у `Command` ковариантный (нужно для `AnyCommand[A | B]`); поведения не меняет
- `selfrot check` сравнивает `AnyCommand` попарно по командам при поиске недостижимых хендлеров

## [0.1.0] — 2026-09-20

Первый выпуск. Поддерживает Bot API 10.3, Python 3.11, 3.12 и 3.13.

### Добавлено

**Типы и методы (генерируются из спецификации Bot API)**
- 400 типов, 185 методов, `scripts/generate_types.py`; суженные типы (`TextMessage`,
  `DataCallbackQuery`, `UserMessage`, ...) для каждого необязательного поля
- 26 видов хендлеров по полям `Update`, фильтры `Has*`, ярлыки контекста (`ctx.answer_photo`, ...)
- методы на самих объектах: `message.answer()`, `message.edit_text()`, `callback.answer()`
- `Bot.defaults` (`parse_mode`, `link_preview_options`, ...), прокси, таймауты, повтор при 429,
  иерархия исключений от `SelfrotError`

**Хендлеры, фильтры, роутеры**
- хендлеры-классы; при создании класса заголовок (`AppContext[TextMessage]`) сверяется с
  гарантией фильтра (`DefinitionError`)
- фильтры: `Text*`, `Command`, `CallbackData*`, `CallbackPayload` (типизированные данные кнопок,
  `pressed_by`), `MemberJoined`, `MemberLeft`, `ChatMemberTransition`, `FromUser`, `InState`,
  `NoState`; комбинаторы `&`, `|`, `~`
- аргументы команд как данные: `CommandArgs`, `Rest`, необязательные аргументы,
  `CommandArgsError` с готовой подсказкой (`usage`)
- дерево роутеров (`routers`, `auto_connect`), мидлвари с `pre_handle` и `post_handle(exc)`,
  `on_error` на хендлере и на диспетчере

**Диспетчер**
- long polling и вебхуки (секрет в заголовке, дедупликация, 503 при перегрузке)
- параллельная обработка апдейтов, порядок по чату или пользователю включается явно
- `on_startup`, `on_shutdown`, остановка по `SIGINT` и `SIGTERM`
- отложенные вызовы: `self.defer(fn, delay=...)` и `after_handle()` (после закрытия хендлера)

**Диалоги и клавиатуры**
- FSM: `States`, `State(Model)` с типизированными данными, `ctx.fsm`, `MemoryStorage(ttl=...)`
- `InlineKeyboard` с проверкой лимитов Telegram

**Инструменты**
- команда `selfrot`: `init` (заготовка проекта), `add router` (файл или папка через `--module`),
  `tree` (роутеры, хендлеры и фильтры), `check` (ошибки и забытые подключения)
- 356 тестов, CI на GitHub Actions (Python 3.11–3.13, pyright, актуальность сгенерированного кода,
  установка пакета), лицензия MIT

### Известные ограничения
- нет локализации и сцен, готового хранилища FSM в Redis, скачивания файлов и загрузки файлов
  внутри альбомов, сборщика reply-клавиатур
- отложенные вызовы и `MemoryStorage` живут в памяти и пропадают при перезапуске бота
- API может меняться (альфа)
